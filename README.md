# «Решено» — куда пойти в Красноярске

Чат-бот и мини-приложение в MAX для трека «Досуг и развлечения».

## Назначение

**Продукт:** мини-приложение в MAX для жителей Красноярска, которое помогает быстро решить, куда пойти на досуге.

**Проблема:** пользователь открывает афишу и видит слишком много вариантов. Их приходится сравнивать сразу по нескольким параметрам: дата, цена, формат, компания. В итоге он откладывает выбор и никуда не идёт.

**Решение:** три входа, которые ведут к одному результату — подборке конкретных мероприятий. Вход выбирается по тому, насколько ясно пользователь понимает, чего хочет:

| Пользователь… | Вход |
|---|---|
| знает точно, что ищет | 🔎 Поиск и ⚙ «Подобрать» (фильтры) |
| знает примерно (настроение, компания) | Быстрые категории и 🏷 теги настроения |
| не знает вообще | ✨ «Найдём вместе»: акинатор и кубик 🎲 |

**Данные:** 87 мероприятий Красноярска (сентябрь–октябрь 2026) из базы проекта `ГОТОВАЯ_БД.xlsx`. Мероприятия берутся **только** из этой базы (`server/db/events.xlsx`). Какие записи подтверждены афишами, а какие тестовые, отмечено в самой базе.

## Основной пользовательский сценарий

1. Пользователь открывает бота в MAX и нажимает «Начать». Бот объясняет три способа поиска и показывает кнопки «Открыть афишу» и «✨ Найдём вместе» (open_app).
2. **Поиск:** пользователь вводит, например, «Роев ручей» и сразу видит нужное мероприятие.
3. **Фильтры:** «⚙ Подобрать» → дата, время, цена, тип, формат, возраст, «Пушкинская карта». Кнопка «Показать N» заранее показывает, сколько мероприятий найдётся.
4. **Категории:** одно нажатие на «Для пар», «Семьям», «Соло», «Компаниям», «Активные» или «Спокойные», либо выбор нескольких тегов в «🏷 Теги».
5. **«Найдём вместе»:** до 4 вопросов (энергия, компания, помещение или улица, бюджет) в случайном порядке и с разными формулировками. Когда остаётся ≤ 3 вариантов, появляется результат. Кнопка «🎲 Выбери за меня» бросает кубик и выбирает один вариант.
6. **Карточка:** описание, кто выступает, дата и время, адрес, цена, возраст. Кнопка «🎟 Билеты / записаться» ведёт по ссылке из базы. Если ссылки нет, показывается «✅ Вход свободный».

## Функции

### 1. Поиск
- Ищет по четырём полям сразу: название, исполнитель, адрес, теги настроения.
- Не учитывает регистр, `ё` и `е` считаются одной буквой, знаки препинания игнорируются.
- Упрощённая морфология: у слов из 5–6 букв перед сравнением отрезается 1 символ, у слов из 7 и более — 2 («концерт», «концерты», «концертом» дают одинаковый результат). Это грубый стемминг, а не морфоанализ.
- Каждое слово запроса должно найтись в объединённой строке полей (логика «И»).
- Активный поиск снимает выбранные быструю категорию и теги и ищет по всей базе. Фильтры из «Подобрать» продолжают действовать.

### 2. Фильтры («⚙ Подобрать»)
Дата (от–до, пересечение с периодом мероприятия), время начала (от–до), цена (от–до и «только бесплатные»), тип (несколько сразу), формат (в помещении / на улице / неважно), возраст («не старше выбранного»), «Пушкинская карта». Все условия объединяются через «И». «Показать» применяет фильтры, «Сбросить» очищает всё.

### 3. Категории и теги
- 6 быстрых категорий. «Для пар», «Семьям», «Соло», «Компаниям» работают по полям `pair`, `family`, `solo`, `group_of_friends`. «Активные» и «Спокойные» — по группам тегов из словаря акинатора (`server/src/data/catalog.js`). Повторное нажатие снимает категорию.
- «🏷 Теги» — все 28 тегов с листа «теги для акинатора». Можно выбрать несколько, они объединяются через «ИЛИ».

### 4. Сортировка
«Сначала ближайшие» (по умолчанию; постоянные форматы считаются доступными сегодня), «Новинки» (порядок добавления в базу, от последних к первым), «Сначала дешевле», «Сначала дороже».

### 5. «Найдём вместе» (акинатор)
- Четыре измерения: энергия, компания, помещение или улица, бюджет. Порядок случайный. У каждого измерения 4–5 формулировок со своими вариантами ответа, всего 17 вопросов.
- Недавно показанные формулировки (последние 10) запоминаются на устройстве и не повторяются, пока есть свежие.
- Измерения, которые не сужают оставшийся пул, пропускаются. Ответы, после которых не осталось бы ни одного мероприятия, не показываются.
- Как только вариантов ≤ 3, диалог заканчивается раньше, не дожидаясь 4-го вопроса.
- В результате показываются 3 ближайших по дате мероприятия, по возможности разных типов. «🎲 Выбери за меня» бросает кубик: подсветка пробегает по карточкам и останавливается на случайной. Можно бросить ещё раз или начать заново кнопкой «Попробовать снова».

### 6. Карточка мероприятия
В списке: иконка типа, название, дата и время, теги, цена, бейджи возраста и «Пушкинской карты». В полной карточке добавляются описание, исполнитель, полный период и время, адрес, формат, кнопки «Билеты / записаться» (поле `link`) или «Вход свободный», а также «На карте».

### 7. Пагинация
10 карточек на странице, кнопки «← Назад» / «Вперёд →», номер страницы и общее число найденных. После любого изменения поиска, фильтров, категорий или сортировки список возвращается на первую страницу.

Прошедшие мероприятия (дата окончания раньше сегодняшней по Красноярску) в выдачу не попадают.

## Состав и архитектура

```
MAX (мобильный / веб-клиент)
 ├─ Чат с ботом ──────────── Bot API MAX (platform-api2.max.ru) ◄─┐
 └─ Мини-приложение (React + MAX UI + MAX Bridge)                  │
        │  HTTPS                                                   │
        ▼                                                          │
 Сервер «Решено» (Node.js, один контейнер) ────────────────────────┘
   ├─ Каталог      server/db/events.xlsx → чтение при старте (без сторонних библиотек)
   ├─ REST API     поиск, фильтры, сортировка, пагинация, акинатор
   ├─ Бот          long polling или webhook /bot/webhook
   └─ Статика      собранное мини-приложение
```

| Файл | Назначение |
|---|---|
| `server/db/events.xlsx` | База мероприятий (копия `ГОТОВАЯ_БД.xlsx`) |
| `server/src/data/xlsx.js` | Чтение xlsx на встроенных модулях Node.js (zip + XML) |
| `server/src/data/catalog.js` | Нормализация строк базы, иконки типов, группы тегов |
| `server/src/search.js` | Поиск, фильтры, категории, теги, сортировка, пагинация |
| `server/src/akinator.js` | Вопросы и логика «Найдём вместе» |
| `server/src/app.js` | HTTP API и раздача статики |
| `server/src/bot.js`, `maxApi.js` | Чат-бот и клиент Bot API MAX |
| `server/src/auth.js` | Проверка подписи `initData` MAX |
| `webapp/src/screens` | Экраны: `Catalog`, `FilterSheet`, `TagSheet`, `Akinator`, `EventDetail` |

### Внутренний API мини-приложения

Эти HTTP-методы — серверная часть мини-приложения, а не отдельный публичный продукт. Мини-приложение обращается к ним с того же адреса. OpenAPI и DATA-API.yaml не требуются.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/health` | Проверка работоспособности и число мероприятий |
| GET | `/api/meta` | Справочники: типы, теги, категории, сортировки, диапазоны |
| POST | `/api/events/search` | `{ q, filters, quick, tags, sort, page }` → `{ items, total, page, pages }` |
| GET | `/api/events/:id` | Одно мероприятие |
| POST | `/api/akinator` | `{ answers: [{questionId, value}], avoid: [questionId] }` → следующий вопрос или `results` |
| GET | `/api/me` | Пользователь MAX по подписанному `initData` |

## Запуск одной командой (Docker)

```bash
cp .env.example .env        # впишите MAX_BOT_TOKEN
docker compose --profile tunnel up --build -d
```

Команда поднимает сервер (мини-приложение, API и чат-бот) и HTTPS-туннель Cloudflare. Без туннеля, только локально: `docker compose up --build -d`.

Приложение: http://localhost:8080, проверка: http://localhost:8080/api/health.

Публичный HTTPS-адрес мини-приложения:

```bash
docker compose logs tunnel | grep trycloudflare.com
```

Этот адрес передаётся организаторам для привязки мини-приложения к боту и указывается в `WEBAPP_URL` в `.env` (после изменения `.env`: `docker compose up -d`).

На Windows запуск и остановку выполняют файлы `Запустить.bat` и `Остановить.bat`. Docker Desktop должен быть запущен.

Файл `webapp/index.html` — шаблон для сборщика Vite, открывать его напрямую нельзя. Мини-приложение отдаёт сервер.

### Остановка и повторный запуск

```bash
docker compose --profile tunnel down          # остановить
docker compose --profile tunnel up -d         # запустить снова
```

### Обновление базы мероприятий

Замените `server/db/events.xlsx` новой версией (структура листов и колонок та же) и пересоберите образ: `docker compose up --build -d`. Другой файл можно подключить без пересборки через переменную `DB_PATH` и том Docker.

### Локальная разработка без Docker

Требуется Node.js 22+.

```bash
cd server && npm start                          # API и бот на :8080
cd webapp && npm install && npm run dev         # фронтенд на :5173, /api проксируется на :8080
cd server && npm test                           # автотесты (17 шт.)
```

## Параметры окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `MAX_BOT_TOKEN` | — | Токен бота MAX. Без него мини-приложение работает, а бот отключён |
| `BOT_MODE` | `polling` | `polling`, `webhook` или `off` |
| `WEBHOOK_URL` | — | HTTPS-адрес на порту 443 для режима webhook (путь `/bot/webhook`) |
| `WEBHOOK_SECRET` | — | Секрет, проверяется в заголовке `X-Max-Bot-Api-Secret` |
| `WEBAPP_URL` | — | HTTPS-адрес мини-приложения (запасная кнопка-ссылка) |
| `MAX_WEBAPP_NAME` | username бота | Значение `web_app` для кнопки `open_app` |
| `HOST_PORT` | `8080` | Порт на хосте |
| `DB_PATH` | `server/db/events.xlsx` | Путь к базе мероприятий |
| `INIT_DATA_MAX_AGE_SEC` | `86400` | Срок действия подписи `initData` MAX |
| `DEV_AUTH` | `false` | Только для локальной проверки: `/api/me` без MAX вернёт тестового пользователя |

**Порты:** контейнер слушает `8080`, наружу пробрасывается `HOST_PORT`. Туннелю входящие порты не нужны.

## Зависимости

- Сервер: Node.js 24 (`node:24-alpine`), без npm-зависимостей. Формат xlsx читается встроенными модулями `zlib` и `fs`.
- HTTPS-туннель: `cloudflare/cloudflared:2026.9.3`.
- Мини-приложение: `react` 19.2.8, `react-dom` 19.2.8, `@maxhub/max-ui` 0.5.0, `@fontsource-variable/manrope` 5.3.0 (шрифты Manrope и Glametrix под лицензией SIL OFL 1.1 хранятся локально, без внешних запросов; текст лицензии Glametrix — `webapp/src/fonts/OFL.txt`), `vite` 7, `@vitejs/plugin-react` 5. Версии зафиксированы в `package-lock.json`.
- MAX Bridge: `https://st.max.ru/js/max-web-app.js`.

## Работа с данными

- Источник мероприятий — только `server/db/events.xlsx`, лист `events`: `id, title, description, category, tag_1..3, date, time_start, time_end, address, indoor_outdoor, price, price_type, age_restriction, family, pair, solo, group_of_friends, pushkin_card, link, recurrence, performer`. Словарь тегов берётся с листа «теги для акинатора».
- База читается при старте сервера. Строки с нераспознанной датой пропускаются и попадают в лог.
- `date` бывает одной датой (`2026-10-07`) или периодом (`2026-09-26 – 2026-10-31`).
- В ссылки на билеты допускаются только `http(s)`.
- Персональные данные не хранятся. На сервере остаётся только служебный маркер бота (`data/state.json`). Недавние вопросы акинатора запоминаются в `localStorage` устройства.
- Секреты передаются только через `.env`, который не попадает ни в репозиторий, ни в образ.

## Работа с тестовыми данными

Какие записи базы подтверждены афишами, а какие тестовые, указано в самой базе. Приложение показывает их одинаково. Чтобы обновить данные, замените xlsx (см. выше).

## Пошаговый сценарий проверки

1. `docker compose up --build -d`, открыть http://localhost:8080 (или бота в MAX → «Открыть афишу»).
2. В поиске ввести `Роев ручей`. Должен найтись 1 результат: «Поход в парк флоры и фауны „Роев ручей“».
3. Очистить поиск, нажать «🎉 Компаниям», потом «💞 Для пар». Счётчик «Найдено» меняется, активна одна категория.
4. «⚙ Подобрать» → «Только бесплатные». На кнопке видно «Показать N», после нажатия в списке только бесплатные мероприятия.
5. Сортировка «Сначала дороже»: цены идут по убыванию. «Вперёд →» открывает страницу 2.
6. «Сбросить всё», затем «✨ Найдём вместе»: ответить на вопросы. Когда вариантов останется ≤ 3, появится результат.
7. «🎲 Выбери за меня»: кубик выберет одну карточку, остальные станут бледнее.
8. Нажать на карточку. Откроется детальная страница с кнопкой «Билеты / записаться» или «Вход свободный».
9. «Попробовать снова». Вопросы будут сформулированы иначе, чем в прошлый раз.

```bash
curl -s localhost:8080/api/health
curl -s -X POST localhost:8080/api/events/search -H "Content-Type: application/json" -d '{"q":"Роев ручей"}'
curl -s -X POST localhost:8080/api/akinator -H "Content-Type: application/json" -d '{"answers":[]}'
```

## Примеры ожидаемого поведения

| Действие | Результат |
|---|---|
| Поиск `концерт` / `КОНЦЕРТЫ` / `концертом!` | одинаковое число результатов |
| Поиск `Гранд несуществующее` | 0 результатов (все слова должны совпасть) |
| Поиск при выбранной категории «Семьям» | категория снимается, поиск идёт по всей базе |
| Теги «мистическое» + «экстремальное» | мероприятия хотя бы с одним из тегов |
| Дата «с» позже даты «по» | подсказка об ошибке, кнопка «Показать» неактивна |
| Фильтры без результатов | кнопка «Ничего не найдено» неактивна; в списке — «Сбросить всё» и «Найдём вместе» |
| Некорректный параметр API | `400 {"error": "..."}` |
| Нет сети | сообщение об ошибке и кнопка «Попробовать ещё раз» |

## Известные ограничения

- База загружается при старте: после замены xlsx сервер нужно перезапустить.
- Время начала в базе используется как есть. Часть записей начинается в 02:00–07:30. Если это ошибка конвертации часовых поясов, её нужно исправить в самой базе.
- Сегодняшние мероприятия показываются до конца дня, даже если время начала уже прошло.
- Формат поля `web_app` кнопки `open_app` нужно сверить с актуальной документацией MAX. Если платформа отклонит кнопку, бот отправит ссылку на `WEBAPP_URL`.
- Тактильный отклик и системная кнопка «Назад» работают только в клиенте MAX.
- Быстрый туннель Cloudflare выдаёт новый адрес при каждом перезапуске и работает, пока включён компьютер с Docker. Для постоянной работы нужен хостинг или именованный туннель с собственным доменом.
- Данные о мероприятиях подготовлены вручную и хранятся в xlsx. Интеграции с внешними афишами (Культура.РФ, сайты площадок) нет: это следующий шаг после MVP.
